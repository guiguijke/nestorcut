# Reprise du pilotage — point d'étape et plan pour le nouvel implémenteur (2026-09-13)

Document de passation écrit par le vérificateur à la demande du propriétaire
(changement d'agent implémenteur le 13/09). Il dit **où l'on en est, ce qui
tourne en production, ce qui reste, dans quel ordre, avec quelles règles** —
et renvoie aux documents qui font foi. À lire en entier avant le premier
commit.

## 0. Les rôles et la boucle de travail

- **Le propriétaire** (Guillaume) décide du produit, des priorités et de
  l'argent. Il relaie les rapports de l'implémenteur au vérificateur et
  inversement. Il ne lit pas le code : les messages sont courts, en français
  clair, avec un bloc « Pour l'agent » copiable.
- **L'implémenteur** livre **un lot = un commit (ou peu) + un rapport** dans
  le document du chantier (section « Rapports par lot »), avec : ce qui est
  livré, les verrous rejoués et leurs chiffres, les non-faits **dits
  franchement**, les points à arbitrer. Il **ne déploie qu'après le GO** du
  vérificateur. Forme des rapports : constat par constat, chiffres mesurés,
  aucune affirmation sans mesure (voir les rapports existants comme modèles).
- **Le vérificateur** (Claude, cette session) rejoue les verrous sur son
  poste, écrit une section « vérification » dans le même document, donne
  **GO / NO-GO**, tranche les arbitrages techniques (délégués par le
  propriétaire) et les consigne au registre du masterplan.
- La boussole : `docs/MASTERPLAN-2026-09-05.md` §0 (la référence du nesting
  dans le navigateur) et §8 (forme des instructions). La carte des documents :
  `docs/README.md`. Les pièges techniques : `AGENTS.md` §2 (à lire avant tout
  code moteur, worker, miroir JS ou visualizer). La page de suivi lisible du
  propriétaire : `docs/RESTE-A-LIVRER-2026-09-10.html` (priorités numérotées
  en clair).

## 5. Lot J4 — brancher le `.job` au produit (consigne fermée)

Objectif : un utilisateur dépose un `.job` SheetCam, NestorCut neste ses
pièces avec l'espacement et les réserves qui en découlent, et il télécharge
un `.job` par tôle que SheetCam ouvre avec le bon ordre de coupe. Chemin
navigateur d'abord (masterplan §0), un seul code (`shared/`).

1. **Dépôt** : `.job` accepté dans `DxfUpload.vue` (signature, pas
   l'extension — piège #31 ; un `.job` = texte INI + `[BinaryDataStart]`).
   Les dessins référencés (`DrawingFile`) ne sont pas dans le `.job` : la
   fiche demande les DXF correspondants s'ils manquent (par nom de fichier,
   règle 9), ou les prend s'ils sont déposés ensemble. Une fiche par dessin,
   quantité = nombre d'exemplaires dans le `.job`.
2. **Réglages pré-remplis** (modifiables, jamais imposés) : espacement =
   `spacingFromKerf(kerf)` ; tôle = `[Work]` ; `pierceMarginMm` réglage
   utilisateur, défaut `DEFAULT_PIERCE_MARGIN_MM` (3 mm, **valeur à confirmer
   par le propriétaire**) ; table `Start position → coin` (`START_CORNERS`)
   **à confirmer par un essai SheetCam**, sinon repli sur la plus longue
   arête droite (déjà codé).
3. **Nesting** : les polygones nestés sont `partWithReserve(part)` (réserve
   locale), le `.job` rendu garde les contours réels ; `nestedIn` vient du
   post-pass (`holesFilled`, membres par trou), pas d'une déduction
   géométrique.
   **Réserve d'amorce des TROUS (défaut constaté à la recette du 13/09)** :
   l'amorce et le perçage d'un contour intérieur tombent DANS le trou, là
   où le remplissage pose des pièces ; il faut soit réserver au point de
   départ prédit du trou une zone d'exclusion vers l'intérieur (amorce +
   disque) soustraite de la zone libre du remplissage, soit imposer le point
   de départ du trou après nesting là où il reste de la place, si le format
   le permet. Détail et verrous : étude §9, « Recette SheetCam — verdict ».
   Rien n'est déployé tant que la recette machine rejouée n'est pas OK.
4. **Sortie** : un bouton « Télécharger le .job » par tôle
   (`nestedJobsPerSheet`), nom `<nom>_tole<k>.job` ; **normaliser l'angle
   écrit dans (−π, π]** avant l'écriture (le fichier de recette porte
   `Angle=-6.283` pour un θ = 2π émis par le moteur — à régler côté J2/J4,
   une ligne) ; constats des réserves refusées (`part.reserve.reason`) dans
   la fiche, FR et EN.
5. **Langues** : tout libellé dans `app/utils/i18n.js`, anglais ET français
   (`i18nDict.test.js` attrape une clé manquante).
6. **Verrous** : vitest ; harnais navigateur dédié (`scripts/qa-e2e-job.mjs`,
   fichiers privés passés par variable d'environnement, copies anonymes en
   sortie) : dépôt d'un `.job` + ses DXF → nesting → `.job` téléchargé
   **identique à la structure de la recette** (Count, `copyOf`,
   `Optimisation=3`, `[OpOrder]` nichées puis hôte, chemins masqués, bloc
   binaire intact) ; harnais 900 pièces deux configurations inchangé pour
   les jobs sans `.job` ; déterminisme natif ≡ wasm intact (aucun code
   moteur). **Recette machine** : le propriétaire ouvre le fichier produit
   dans SheetCam ; son verdict va en §9 avant tout déploiement.
7. Miroir serveur (« Nos serveurs ») : lot J5, après J4, même plomberie
   qu'au lot E2 (champs additifs sur le document fichier, worker
   fileprocessing).
